# MatrixDesign-minimal.md — 极简主义 Matrix 风设计规范

> 状态：Active / 「极简 Matrix 风」任务的单一事实源
>
> 适用：用户要求「极简风 / 极简主义 / 简约 / 克制」或类似的 UI 风格设计任务；未指明风格时默认用本规范
>
> 与完整宪章的关系：本规范是 `DESIGN.md`(ZION 视觉设计宪章)的**极简子集 + 提炼规则**。宪章保持完整不动——用户要求「电影化 / 电影风 / 强烈视觉效果 / 更 Matrix 风」时改用 `DESIGN.md`。两文档冲突时,极简任务以本规范为准。
>
> 一句话：**Matrix 的辨识度来自黑场、磷光绿、字形与状态叙事,不来自效果堆叠。极简模式用最少的不变量保住世界观,其余一律让位给可读性。**

## 1. 极简命题

每次极简视觉任务应满足:

- 第一眼仍认出这是 Matrix 世界:黑场 + 磷光绿 + 专用字形,缺一不可;其余都可缺。
- 大量信息/组件堆叠同屏时,画面仍然干净:任何一屏的「正在动的东西」不超过一处,装饰性元素总量只减不增。
- 简约不靠全局削弱效果达成,靠**少放元素**达成——宁可整块不要,不把每块都调淡。

> 宪章原文(§1):「信息层与氛围层共同设计。通过局部遮罩、对比、景深和焦点模式保护可读性,而不是全局削弱效果。」

## 2. 保留的视觉语法(宪章子集)

以下三条是极简模式的全部语法来源,摘录原文:

> **数字雨不是墙纸,而是模拟层**(§4.1):「字形可以固定在网格中,真正移动的是亮度波」「明暗与速度分层,接近白色的高能头部,拖尾、辉光、雾化和大块黑色留白」。
> 极简执行:数字雨只作**单层、低速、低亮度**的远景氛围,不参与叙事、不做变体(无涟漪/倾斜/显影)。

> **Zion 控制室几何**(§4.2):「用环形结构、地图拓扑、透明叠层、细线网格、单色体积和局部高亮表达庞大系统。」
> 极简执行:只取「细线网格 + 局部高亮」。1px 发丝线、零圆角、单色——结构感来自对齐与分隔,不来自边框装饰。

> **全屏操作台密度**(§4.3):「稳定的空间分区、统一字形和一致框架能承载很高的信息密度。屏幕可以像驾驶舱一样被充分利用;密集区与巨大暗场并置,比平均分布更有戏剧性。」
> 极简执行:这是堆叠时保持简约的核心——**密集区与暗场并置**,信息可以密,但分区必须稳定、边线必须统一。

## 3. 构图纪律(堆叠场景的硬规则)

> 宪章原文(§5.1):「每屏一个视觉主角。」「次要区域主动让出亮度、运动、尺度或清晰度。」

> 宪章原文(§5.3):「允许某一区域极密、另一处几乎全黑。用负空间放大能量头部、关键文字和机械轮廓。平均亮度、平均间距、平均卡片尺寸通常会削弱电影感。」

提炼为四条可执行规则:

1. **一个主角**:一屏只允许一个视觉主角(一次工具写入、一个状态字、一条链路)。极简模式下主角用「亮度」表达,不用「运动+发光+音效」叠加表达。
2. **一个动源**:同屏正在进行的动画 ≤1(流式光标 / 雨轨 / 脉冲,任一)。其余元素静止。这是堆叠不过载的第一纪律。
3. **暗场是成分**:每个视图保留成片纯黑负空间;组件之间的留白优先于组件内部的装饰。
4. **密度靠分区不靠卡片**:信息堆叠时用统一分区 + 发丝线分隔收纳,禁止每个模块各自发明卡片样式(边框/阴影/圆角/底色叠加)。

## 4. 色彩与字形(克制子集)

> 宪章原文(§6.1)摘录:「深黑与绿黑:空间、机器内部、未显影信息。」「磷光绿:活跃生命、可执行路径、模拟层能量。」「近白绿:高能头部、瞬间峰值、最强焦点。」「琥珀/橙红:物理热量、警告、旧设备、危险确认。」「色相不是状态的唯一载体;同时使用形态、位置、图标、文字、声音与运动。」

极简执行:

- 常态四色封顶:黑场底、磷光绿(活跃/可交互)、近白绿(仅当前焦点/峰值,全屏 ≤1 处)、琥珀/红(仅警告与危险)。
- 紫红/毒黄/电蓝等扩展色相(§6.1 后段)**极简模式不用**。
- 装饰性 glow/text-shadow 全关;亮度对比本身已够表达层级。

> 宪章原文(§6.2)摘录:「操作字形:等宽字体,清晰显示代码、路径、时间、状态与命令。」「中文正文:优先可读,必要时用实体暗底、局部去辉光和更高行距保护。」

极简执行:

- 只用两档字形:操作字形(等宽,承载一切信息与控件)+ 氛围字形(Matrix 字形集,**仅**用于数字雨与流式光标等已有语义位)。
- 叙事字形(超大/窄体/扩字距/纵向排版,§6.2)极简模式**不用**。

## 5. 状态编舞(极简映射)

宪章 §7 的状态表在极简模式仍然成立,但每个状态只许**一个**信号,且优先用文字/色彩/形态,最后才是运动:

| 状态 | 极简信号(只许一件) |
|---|---|
| READY / SETTLED | 低速数字雨基线,无其他运动 |
| STARTING | 主角区域亮度抬升一次 |
| THINKING / STREAMING | 流式光标(字形蛾)或单行状态文字 |
| TOOL START / END | 工具卡触点变色 + 一次性落定(无冲击波扩散到屏外) |
| CANCELLING / ERROR | 色相转为琥珀/红 + 明确文字;无屏幕级抖动/污染 |

> 宪章原文(§7):「视觉必须来自真实状态。」——极简模式同样禁止假数据与假进度(见 §7 边界)。

## 6. 禁用清单(极简模式明确不做)

以下宪章能力属于电影风档位,极简任务**禁用**:

- CRT 材质管线(§4.4):扫描线贴图、曲率、RGB 分离、抖动、烧屏余辉——全部不做
- 电影级 FUI 的满屏转场/巨型叙事字/全息投影(§4.5、§3 末段)
- 生物机械链路的持续性装饰动画(§4.6「装饰动画可以持续存在」一条在极简模式不适用;状态动画保留但收敛到单次)
- 声音层(§8):不加音效;既有开关类音效保持关闭默认
- 多层辉光/bloom、粒子、视差、鼠标跟随光
- 阴影、圆角、渐变卡片底——极简模式的材质只有:黑场、发丝线、字形

## 7. 不可交换的边界(与宪章 §10 全等)

极简不豁免任何产品边界,原文照录:

> - 展示真实事件、任务、文件、耗时和结果。未知数据明确标记为未知,不生成假进度、假 token、假安全结论或假工具调用。
> - 对外只呈现可交付的 reasoning 摘要、计划、动作和证据,不暴露隐藏思维链、凭据、系统提示或敏感环境信息。
> - 提交、删除、终止、重试、项目切换等关键操作始终有可理解的文字、键盘路径、焦点状态和必要确认。
> - 颜色、声音和动画均有语义等价物;主要交互具有正确的原生语义或 ARIA。
> - 遵守闪烁安全,提供暂停/静音/Reduced 路径,并保证错误时仍可操作。

降级(§9 子集):`prefers-reduced-motion` 时直接显示终态,数字雨画静态帧;「效果降级应稳定、无拉伸、无中间帧闪现」。

## 8. 完成标准(极简任务 checklist)

- 静态截图:黑场 + 磷光绿 + 字形,一眼 Matrix;同时**画面元素可数**——控件之外无一件纯装饰
- 任一时刻屏上运动元素 ≤1;glow/阴影/圆角/渐变为 0
- 信息堆叠场景(长会话 + 多工具卡 + diff 卡同屏)仍保持分区稳定、暗场成片
- 所有状态信号有真实数据源;文本/代码/输入清晰可读(中文行距与暗底保护生效)
- 键盘、焦点、Reduced 路径可用;文档已同步
